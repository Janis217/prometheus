Scope for this milestone:

Implement the first PROMETHEUS disaster mission configuration prototype in the existing repo,
not as a separate project.

Goal:
Create a new core agent that behaves like a structured mission-configurator for disaster response.
The prototype should capture a mission, ask for missing critical information, recommend a physical
AI embodiment, identify safety conditions and approval needs, and return an execution-ready mission brief.

The implementation must follow the existing repo pattern for core agents and stay intentionally narrow.
Do not build a broad emergency system or a generic chatbot; keep the first milestone demonstrable and state-machine driven.

Required work:

1. Add a new agent definition in the existing core agentdefs package.
2. Use the same pattern as the current single-state demo agents.
3. Define a weather/fire/search/rubble style mission configuration flow with a small, structured prompt set.
4. Ensure the agent can:
   - capture mission objective, urgency, and location
   - ask for missing critical facts
   - choose a likely embodiment (drone, ground robot, dog robot, humanoid, or unknown)
   - define constraints, required perception, required behavior, and first action
   - block unsafe or incomplete missions until approval or clarification is available
5. Produce a structured final output that can be inspected and reviewed, not just free-form text.
6. Add the smallest meaningful validation: success path, missing-info path, and unsafe/guard path.
7. Keep the implementation aligned with the existing Valerian demo architecture and access-code flow.

Do not introduce unrelated architecture changes or broad refactors.

coherent change and verify it with targeted tests.
